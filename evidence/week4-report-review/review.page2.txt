/Hình 2.1. Giao diện Nhịp Security sau khi admin01 đăng nhập Web B.2.2. Cấu hình OIDC Client và phân quyền Web BTạo security-dashboard là public client, dùng Authorization Code Flow và PKCE S256, Audience security-api và scope basic để token có sub. Web A giữ employee-portal và employee-api. Backend xác minh chữ ký, issuer, thời hạn, azp, audience theo client, hồ sơ và vai trò; token Web B không được dùng để đọc nghiệp vụ chấm công.Kết quả: admin và auditor được vào Web B; auditor bị từ chối API quản lý tài khoản. employee/manager bị chặn tại UI và API với HTTP 403 nhưng vẫn dùng được Web A theo quyền.
